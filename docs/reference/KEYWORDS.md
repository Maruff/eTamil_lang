# eTamil Keyword Reference

Every keyword in the language, grouped as the lexer groups them.

Each row lists the forms that produce the same token: Tamil script, the
romanized (ezuqqu) spelling, and where one exists an English alias. All
forms are interchangeable in source code.

The three Tamil nasals stay distinct in romanized form: **ண = `N`, ந = `n`,
ன = `Z`**.

The **Token** column is the name the compiler uses internally. It is not a name
you can write, and it is not how anything is stored: **a name is kept exactly
as you typed it.** `வங்கி = 5` creates a variable called `வங்கி`, and
`{வரி: 100}` produces the field `வரி`.

The consequence, which is a real difference in meaning: `{வரி: 1}` and
`{vari: 1}` are *different* fields, and `வருவாய்` and `varuvAy` are different
variables. Pick one spelling per program.

Type keywords and SQL clause keywords are **hard reserved** and cannot be names
at all. Financial keywords are not reserved — `தொகை` is a perfectly good name
for an amount.

> Generated by `scripts/generate_keywords.py` from `etamil_compiler/src/lexer.rs`.
> Do not edit by hand — rerun the script after changing the token list.

## Literals

| Form | Example | Notes |
|---|---|---|
| Number | `1500`, `99.99` | fixed-point decimal — `0.1 + 0.2` is exactly `0.3` |
| Percentage | `20%` | converted at lex time to exactly `0.20` |
| String | `"vaNakkam"` | `\n` `\t` `\r` `\"` `\\` are escapes; any other backslash is kept as written, so `"C:\kaNakku"` stays whole. A line break typed inside a literal is always `\n`, because a file saved with CRLF endings is read as LF — only the `\r` escape puts a carriage return in a string |
| Identifier | `varuvAy`, `வருவாய்` | Tamil letters, ASCII letters, digits, underscore |
